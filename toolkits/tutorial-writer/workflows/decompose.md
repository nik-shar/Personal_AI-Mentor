# Decompose

The first decision is whether the request needs decomposition at all.

## Flow

1. **Read the full request + mentor guidance.** The emphasis block tells you
   the actual weakness. If the request names ONE topic and the guidance
   describes ONE gap against it — no split. Go straight to `write-tutorial`.
2. **Ask: does a split help the learner?** Split when the goal spans clearly
   different skill areas, when no single note could be worked through in
   45–60 minutes, or when prerequisites would be confusing without being
   explicit. Otherwise keep it as a single tutorial node.
3. **If splitting:** produce a DAG-lite outline — 2 to ~8 subtopics, ordered
   by day, each with honest `what_to_cover`, a content-type classification,
   and prerequisite links using exact subtopic titles. Cap the split to what
   genuinely needs separating; a 3-hour session is not a 12-topic roadmap.
4. **If NOT splitting:** produce exactly one outline node whose title is the
   topic and whose `what_to_cover` is built from the mentor's emphasis —
   the weaknesses are the sections.

## Rules

- Estimated hours per node: 0.5–4h, by real complexity, not round numbers.
- Entry-level nodes have empty prerequisites; advanced nodes name theirs.
- The content-type must reflect what best teaches THAT topic
  (conceptual / algorithmic / hands_on_code / reference), never a default.
- The graph title includes the timeframe when one exists ("X — 5-Day
  Roadmap"); single-topic graphs use a plain descriptive title.
